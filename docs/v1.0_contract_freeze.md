# v1.0 contract freeze

This page is the audit of every public or machine-readable interface Membrane Visual QC exposes,
and the explicit decision of what is frozen ahead of a v1.0 release. "Frozen" means: this project
commits not to change the interface's existing shape or meaning in a way that breaks an existing
consumer, without going through the deprecation process in `docs/versioning_policy.md`. New,
additive capability is always allowed; breaking an existing consumer is not, once an interface is
frozen.

This audit was performed against `main` at commit `eb67cf71a5ebd872420b6835b8bb239e387a4f48`
(active development version `0.8.0.dev0`, most recent published release v0.7.0). Every claim below
is grounded in the cited source file; see `docs/versioning_policy.md` for how this list is meant to
evolve and `docs/compatibility_matrix.md` for what is validated on which platform.

## How to read this page

- **Frozen** -- this interface's existing shape is a hard compatibility commitment as of this
  audit. It is the v1.0 candidate contract for that interface today; breaking it before v1.0 still
  requires the deprecation process.
- **Not frozen** -- explicitly excluded from any compatibility commitment; may change in any
  release, including a patch release, without deprecation.
- **Internal** -- not a public interface at all (implementation detail); consumers must not depend
  on it.

## 3. Batch modes (frozen, closed set)

`membrane_vqc.batch_contracts.MODES`: `legacy_global_z`, `planar_orientation`, `pdbtm_local`,
`pdbtm_cache`, `pdbtm_opm_comparison`. This is a closed enumeration -- no other string is accepted
for `analysis.mode`. Frozen: these five names and which report schema each produces (see
`docs/batch_plan_reference.md#6-each-supported-mode`). Not frozen pre-v1.0: a sixth mode may be added
additively.

## 5. Batch/single-structure status vocabulary (frozen)

Every literal in `docs/status_vocabulary.md` is frozen: job status (`SUCCESS`, `REVIEW_ITEMS`,
`INSUFFICIENT_CONTEXT`, `ANALYSIS_ERROR`, `INPUT_REJECTED`, `CANCELLED`, `SKIPPED_DEPENDENCY`),
batch run `overall_status` (`COMPLETED`, `COMPLETED_WITH_ERRORS`, `FAILED_FAST`, `CANCELLED`),
single-structure `summary.overall_status` (`NO_FLAGS`, `REVIEW_ITEMS`, `INSUFFICIENT_CONTEXT`,
`ANALYSIS_ERROR`), review severity (`WARNING`, `INSPECT`), and result-artifact availability
(`VERIFIED`, `MISSING`). None of these values may be renamed, repurposed, or removed. New values
may be added additively (for example, a future job status), which is why consumers must treat an
unrecognized literal as "handle conservatively," not as an error.

## 6. Error code vocabulary (frozen, additive-only)

Every stable, machine-checkable error/exception identifier below is frozen. An existing code's
string value and its general failure category may not change; new codes may be added.

- **Exception class hierarchy** (`membrane_vqc/errors.py`): `MVQCError` (base) with subclasses
  `InputValidationError`, `StructureParseError`, `OrientationError`, `ExternalServiceError`,
  `OptionalDependencyError`, `ReportError`, `PyMOLAdapterError`.
- **Cache/provider error codes** (`membrane_vqc.pdbtm_errors.Stage4BErrorCode`, 22 values): see
  `docs/status_vocabulary.md#7-cache-and-provider-error-codes` for the complete list.
- **Batch/result-bundle integrity error codes**: `RESULT_MANIFEST_INVALID`, `REPORT_INVALID`,
  `OUTPUT_COLLISION`, `OUTPUT_SIZE_INVALID`, `OUTPUT_UNAVAILABLE`, `OUTPUT_IDENTITY_CHANGED`,
  `OUTPUT_PATH_UNSAFE`, `SAME_BATCH_ROLLED_BACK` -- see
  `docs/status_vocabulary.md#8-batchresult-bundle-integrity-error-codes`.
- **Other typed exceptions** carrying a stable class identity: `BatchContractError`,
  `BatchPathError`, `BatchResultBrowserError`, `BatchInputRejected`, `BatchExecutionFailed`,
  `BatchCancelled`, `CacheContractError`, `Stage4BError`, `PdbtmCommandError`,
  `ProvenanceConversionError`.

## 7. Cache format (frozen)

`cache-v1` (`membrane_vqc.pdbtm_cache`): fixed on-disk layout under
`<cache_root>/pdbtm-api-v1/cache-v1/` (`blobs/sha256/`, `format.json`, `index.json`, `locks/`,
`quarantine/`, `records/`, `tmp/`), at a location independent of the plugin install directory --
`%LOCALAPPDATA%\MembraneVisualQC\Cache` by default, overridable via the `MVQC_CACHE_DIR`
environment variable. The format-version discriminator is baked into the `cache-v1` path segment
and the internal `format.json` literal; an incompatible future format fails closed
(`CACHE_FORMAT_UNSUPPORTED`), never silently misreads. Frozen: this path layout, the environment
variable name, and the fail-closed behavior on format mismatch. Not frozen: internal blob/index
byte-level details beyond what `docs/status_vocabulary.md` and this page document -- no external
tool should parse cache internals directly instead of going through the plugin.

## 8. Plugin ZIP / manifest format (frozen)

`scripts/build_plugin_zip.py`: single top-level `membrane_vqc/` directory, `PLUGIN_MANIFEST.json`
(`format_version: 1`, `plugin.name`/`plugin.package`/`plugin.version`, a `files` array of
`{path, sha256, size}`), `SHA256SUMS.txt`, deterministic byte-for-byte reproducible build (fixed
1980-01-01 ZIP timestamps). Frozen: this manifest shape and `format_version: 1`'s meaning. A future
manifest format change would require a new `format_version` value, not a silent reinterpretation of
`1`.

## 9. CLI (frozen)

`python -m membrane_vqc.batch_cli validate PLAN.json` -- offline plan validation, no PyMOL import.
Frozen: the `validate` subcommand name, its single positional `plan` argument, its zero exit code
on success and non-zero on failure, and that it prints a JSON object containing at least `contract`,
`jobs`, and `valid` on success.

## 10. Environment variables (frozen)

`MVQC_CACHE_DIR` -- overrides the cache root (`membrane_vqc.pdbtm_cache.select_cache_root()`).
Frozen: the variable name and its meaning.

## 11. Output/manifest layout (frozen as the v1.0 candidate)

The batch output layout documented in full in `docs/outputs_and_manifests.md` -- flat output root,
`<job_id>.json`/`<job_id>.csv` naming, the fixed `batch-result.json` manifest filename, atomic
publication, and the `overwrite`/collision rules -- is hereby declared the frozen v1.0 candidate
contract as of this audit. It was previously documented as "current convention, not yet frozen"
(PR #29); this page supersedes that framing. See
`docs/outputs_and_manifests.md#what-is-stable-vs-not-yet-frozen` for the updated statement.

## 12. Not frozen (explicitly excluded from any compatibility commitment)

- **Scientific thresholds and heuristics** -- hydropathy palette assignments, exposure/RSA bin
  thresholds, local-context distance cutoffs, comparison review bands (5° angle, 2 Å center
  displacement, 2 Å thickness difference), and similar review-heuristic constants. These may be
  refined in any release with a CHANGELOG note; they are scientific review aids, not a machine
  contract, and refining them does not "break" a consumer the way changing a field name would.
- **GUI layout and visual design** -- dialog structure, control placement, colors, and Qt widget
  choices. See `docs/visual_style.md`; a future visual-identity pass is explicitly out of scope for
  every release through v1.0 planning to date.
- **Internal Python module structure** -- `membrane_vqc/*.py` internals (function/class names not
  listed above, module boundaries, private helpers prefixed `_`) are implementation detail. Only
  the PyMOL commands, file-based contracts, CLI, and error-code vocabulary above are the public
  surface; importing internal modules directly is unsupported.
- **`membrane_vqc.qc.LAST_REPORT`** -- an internal, PyMOL-session-scoped module global used by the
  single-structure command/export flow. It is not part of any documented external contract and
  batch/comparison workflows are explicitly designed to never read or write it (see
  `docs/stage5b_gui_batch.md#main-thread-pump-and-cancellation`,
  `docs/stage4c_source_comparison.md#gui-and-lifecycle`).
- **Development/CI tooling** -- `scripts/*.py` beyond the CLI and ZIP-manifest format named above,
  `.github/workflows/ci.yml`, and test-suite internals.
