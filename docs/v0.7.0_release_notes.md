# Membrane Visual QC v0.7.0

Status: **release preparation** for a GitHub prerelease intended for limited public testing.
Publication date, release URL, tag evidence, and authoritative artifact identities are **PENDING**.
PyPI publication is not provided.

This is a compatibility, reliability, and documentation release. It changes no scientific
algorithm, report schema, batch contract, cache format, or GUI layout.

## 1. What changed

- **Historical report compatibility**: restored read compatibility for genuine historical report
  schema 1.0, backed by a frozen historical fixture; `membrane_vqc.report.validate_report()`
  correctly dispatches schema-1.0 reports without requiring the schema-1.1 depth fields introduced
  later.
- **Result-browser reliability**: converted an unhandled exception in the batch result browser into
  a typed `ReportError`, so an invalid referenced report fails cleanly instead of crashing the
  browsing flow.
- **Windows filesystem hardening**: batch execution now fails fast with a clear, typed error on
  permission denial, path-length limits, and other ACL/OS errors during output writes, instead of
  hanging or retrying unboundedly; the atomic temporary-file creation path is now explicitly
  bounded.
- **Missing-plan CLI behavior**: a missing or invalid batch plan now produces a concise, non-zero-
  exit CLI error instead of a raw traceback.
- **Installation and upgrade compatibility**: added an automated clean-install harness
  (`tests/test_plugin_install.py`) and a v0.6.0 -> `0.7.x` upgrade harness
  (`tests/test_plugin_upgrade.py`), both exercised against the genuine, checksum-verified
  `MembraneVisualQC-0.6.0.zip` release asset, plus `docs/compatibility.md` and
  `docs/upgrade_guide.md`. A real-PyMOL owner-observed clean-install/upgrade/rollback pass was
  completed and recorded for the v0.6.0 -> `0.7.0.dev0` pair.
- **Documentation consolidation**: added `docs/index.md` as a central documentation map, plus
  dedicated troubleshooting, status-vocabulary, outputs/manifests, offline-guarantees, and
  coordinate-preservation guides; expanded the tutorial and batch-plan guide to cover every current
  workflow.

## 2. Why it matters

The schema-1.0 and result-browser fixes close two paths where genuinely valid historical data or a
malformed referenced file could previously be mishandled rather than reported cleanly. The Windows
filesystem hardening closes a class of silent-hang failure modes on real Windows filesystems
(permission-denied network shares, long paths). The install/upgrade harness and documentation work
address this project's own previously-acknowledged gap: prior releases had no automated or
owner-observed evidence that PyMOL Plugin Manager's actual graphical install/upgrade/uninstall flow
-- as opposed to the pure-Python logic underneath it -- behaves as documented.

## 3. Upgrade notes

- **Validated upgrade path: v0.6.0 -> v0.7.0 only.** No other version pair is currently verified;
  do not assume support for upgrading from v0.5.0 or earlier directly to `0.7.x` -- upgrade to
  v0.6.0 first if needed.
- **Clean replacement is the recommended and supported upgrade method.** Remove the previous
  plugin's files before installing the new ZIP, rather than relying on Plugin Manager to overlay
  the new ZIP over the old install directory in place. See `docs/upgrade_guide.md`.
- All of your existing reports, batch plans, batch result bundles, and the PDBTM cache are
  unaffected by this upgrade -- none of that data lives inside the plugin's own install directory,
  and none of it is touched by installing a new Plugin ZIP.
- **History is session-only**, unchanged from every prior version -- the Batch review tab's run
  history is never written to disk and is not something an upgrade can lose or need to preserve.
- **No automatic cache migration** occurs, and none is needed for this transition -- the cache code
  itself is byte-for-byte unchanged between v0.6.0 and v0.7.0.

## 4. Compatibility boundaries

- Primary development, manual graphical acceptance, and CI's `Stage 4/5 Windows core` job target
  Windows (validated on Windows 10/11); the pure-Python logic is also tested cross-platform on
  `ubuntu-latest`, but no manual graphical acceptance has been performed on Linux or macOS.
- Manual graphical acceptance has used Incentive PyMOL; no other PyMOL distribution has been
  manually verified.
- Report schemas 1.0-1.4 (`single_structure_review`) and 1.5 (`orientation_source_comparison`,
  validated separately) are unchanged. Batch contracts `mvqc-batch-plan-1.0` and
  `mvqc-batch-result-1.0` are unchanged.
- See `docs/compatibility.md` for the complete, current statement, including what remains
  manual-verification-only.

## 6. Known limitations

Unchanged from v0.6.0, carried forward without modification:

- Execution requires PyMOL and runs sequentially on its main thread; the standalone CLI validates
  plans only.
- Cancellation is cooperative between jobs and at existing safe checkpoints; it does not terminate
  threads or forcibly interrupt a running PyMOL command.
- Batch history is limited to 20 entries in the current dialog session; it is not persisted,
  discovered, or resumable across restarts.
- There is no cache manager, garbage collection, automatic fitting, consensus, provider ranking,
  preferred source, or biological correctness verdict. Stage 5C has not started.
- This is a GitHub prerelease for limited public testing, not a stable v1.0 contract.
- No PyPI publication is provided.

See `docs/known_limitations.md` for the complete list.

## 7. Installation

After publication, download `MembraneVisualQC-0.7.0.zip` and `MembraneVisualQC-0.7.0.zip.sha256`
from the v0.7.0 GitHub prerelease. Verify the checksum, install the ZIP through PyMOL Plugin
Manager, completely restart PyMOL, and open **Plugin > Membrane Visual QC**.

The wheel and source distribution are supplied as GitHub release assets for inspection and
development. The project is not published to PyPI.

## 9. What remains for v1.0

This release does not attempt, and does not claim, any of the following -- all remain explicitly
out of scope until a dedicated future decision:

- a frozen v1.0 output-layout/manifest contract (the current layout is documented in
  `docs/outputs_and_manifests.md` as current convention, not yet frozen);

- PyPI publication;
- automatic cache migration or garbage collection;
- persistent (cross-session) batch history;
- new scientific analysis modes, automatic fitting, consensus orientation, provider ranking, or any
  biological correctness verdict;
- a premium README/visual-identity redesign or GUI visual redesign -- both are reserved for a
  separate, dedicated pre-v1.0 session.
