# Final 1.0.0 release exit criteria

Status: **MET — owner-accepted stable v1.0.0 published 2026-08-14**. This historical gate did not
itself authorize tagging or publication; the owner subsequently provided that authorization.

## Required evidence

- `1.0.0rc1` has completed owner-run manual acceptance against its exact frozen ZIP.
- All required RC CI and post-merge release-build workflows are green and recorded.
- No unresolved BLOCKER or REQUIRED BEFORE RC item exists.
- RC feedback has been triaged with no unresolved regression against the accepted v0.9.0 baseline.
- Every item classified REQUIRED BEFORE FINAL in `docs/releases/1.0.0_readiness.md` is either
  resolved with evidence or explicitly reclassified by the owner with rationale.
- Public commands, batch contracts, report schemas 1.0-1.5, status/error vocabulary, CSV order,
  cache-v1, output layout, and compatibility policy revalidate unchanged.
- A focused final-version clean-install/upgrade/rollback acceptance record is prepared and completed.
- The final Plugin ZIP is deterministic, content-audited, checksum-published, and independently
  re-downloaded after publication.
- Final `1.0.0` evidence freezes the release commit, CI/artifact, annotated tag, release timestamp,
  exact asset set, hashes, manual acceptance, and PyPI non-publication state.

## Explicit non-goals

Final 1.0 does not require Linux/macOS graphical validation, another PyMOL vendor, persistent batch
history, cache auto-migration, source ranking/consensus, or feature expansion. Those remain accepted
limitations or post-1.0 work unless the owner deliberately changes scope.
