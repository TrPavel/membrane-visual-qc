# Membrane Visual QC v0.6.0

Status: **published GitHub prerelease** for limited public testing on 2026-07-31.
PyPI publication is not provided; PyPI publication was intentionally not performed.

## Stage 5A/5B completion

v0.6.0 completes Stage 5A's operational batch contracts and Stage 5B's **Batch review** GUI:

- Stage 5A's versioned `mvqc-batch-plan-1.0` and `mvqc-batch-result-1.0` contracts, validated by a
  PyMOL-free CLI (`python -m membrane_vqc.batch_cli validate PLAN.json`);
- five declarative job modes in one plan: legacy global-z, local planar, local PDBTM, exact cached
  PDBTM snapshot, and local PDBTM–OPM comparison;
- sequential main-thread PyMOL execution, one job per queued Qt-timer event, so the GUI stays
  responsive during a run;
- a dedicated **Batch review** tab with explicit plan/output selection and Validate, showing the
  ordered job queue, live progress, and the current job;
- per-job operational statuses (for example `SUCCESS`, `INPUT_REJECTED`, `REVIEW_ITEMS`) rolled up
  into an overall run status such as `COMPLETED_WITH_ERRORS`;
- a result manifest plus an in-GUI run summary and selected-job detail view;
- explicit, user-initiated output/report reveal actions, with path and content re-verified
  immediately before opening;
- cooperative between-job cancellation with continue-on-error and fail-fast policies, safely
  stopping a run without corrupting completed job output;
- bounded, current-session-only history of completed and cancelled runs (at most 20 entries);
- **Clear history** that clears only the in-memory session list — it never deletes output files on
  disk;
- fully offline execution: no batch path fetches PDBTM or OPM; cached-PDBTM jobs resolve an exact,
  already validated snapshot before the first job runs;
- coordinate preservation identical to the five underlying single-structure workflows — batch
  execution never fits, rotates, translates, or otherwise mutates the input object;
- a vertically scrollable dialog layout (`QScrollArea` on the Single structure and Batch review
  tabs) so the plugin window stays usable on constrained-height screens and under Windows display
  scaling, with no change to any control or behavior.

Stage 5A/5B is operational evidence only: the batch runner and result manifest report execution
status and output identities, never a biological verdict, a preferred/ranked data source, or a
consensus orientation. That boundary is unchanged from Stage 4C's PDBTM–OPM comparison.

## Installation

After publication, download `MembraneVisualQC-0.6.0.zip` and
`MembraneVisualQC-0.6.0.zip.sha256` from the v0.6.0 GitHub prerelease. Verify the checksum, install
the ZIP through PyMOL Plugin Manager, completely restart PyMOL, and open
**Plugin > Membrane Visual QC**.

The wheel and source distribution are supplied as GitHub release assets for inspection and
development. The project is not published to PyPI.

## Security and privacy boundary

- Ordinary tests and package import make no live network request; batch execution performs no
  network retrieval at all.
- Batch input/output paths reject traversal, URL, UNC, device, and reparse-point forms, and refuse
  unrelated output collisions.
- The result manifest never serializes absolute local paths or raw exception text.
- Result open/reveal is user-initiated and re-verifies path and content immediately before opening;
  missing or changed outputs remain unavailable rather than silently substituted.
- Official PDBTM and OPM payloads remain outside Git and all distribution archives.

## Known limitations

- Execution requires PyMOL and runs sequentially on its main thread; the standalone CLI validates
  plans only.
- Cancellation is cooperative between jobs and at existing safe checkpoints; it does not terminate
  threads or forcibly interrupt a running PyMOL command.
- Batch history is limited to 20 entries in the current dialog session; it is not persisted,
  discovered, or resumable across restarts.
- There is no cache manager, garbage collection, automatic fitting, consensus, provider ranking,
  preferred source, or biological verdict. Stage 5C has not started.
- This is a GitHub prerelease for limited public testing, not a stable v1 contract.
- No PyPI publication is provided.

## Operational contracts

Stage 5A introduces `mvqc-batch-plan-1.0` and `mvqc-batch-result-1.0` as operational batch
contracts, not a new report schema. Report schemas 1.0–1.5 are unchanged by v0.6.0 and retain their
v0.5.0 released bytes; the retained v0.5.0 report evidence is not replaced by this release.
