# Membrane Visual QC v0.8.0 — Contract Freeze and Documentation Consolidation

Status: **published GitHub prerelease** for limited public testing on 2026-08-02.
PyPI publication is not provided; PyPI publication was intentionally not performed.

## 1. Overview

v0.8.0 exists to formally audit and freeze every public/machine-readable interface this project
exposes, define the versioning and deprecation policy that governs those interfaces going forward,
and replace scattered, stage-oriented documentation with one coherent, task-oriented documentation
system. It is a stability and documentation milestone on the path to v1.0, not a feature release.

**Runtime scientific behavior is unchanged from v0.7.0.** No report schema, batch contract, cache
format, GUI layout, or scientific algorithm changed in this release; the only source change is the
version-identity string itself.

## 2. What changed

- **Contract inventory** (`docs/v1.0_contract_freeze.md`): 11 PyMOL commands with exact frozen
  parameter defaults, report schemas 1.0-1.5, the `mvqc-batch-plan-1.0` / `mvqc-batch-result-1.0`
  contracts and their 5-mode closed union, the full status/error vocabulary, the `cache-v1` format
  and `MVQC_CACHE_DIR` environment variable, the Plugin ZIP manifest format, and the batch CLI --
  each marked Frozen / Not frozen / Internal, grounded in source.
- **Versioning/deprecation policy** (`docs/versioning_policy.md`): semantic versioning rules pre-
  and post-1.0, schema/contract version-increment rules, and the explicit deprecation process
  required before any frozen interface can break.
- **Canonical documentation system**: `docs/index.md` reorganized into five sections (Using the
  plugin, Reference, Scientific boundaries, Installation and maintenance, Developer/release); new
  `docs/quick_start.md`, `docs/five_mode_walkthrough.md`, `docs/offline_and_safety.md`, and
  `docs/scientific_interpretation.md`; `docs/batch_plan.md` renamed to
  `docs/batch_plan_reference.md`.
- **Compatibility matrix** (`docs/compatibility_matrix.md`): platform x validation-method grid,
  schema/contract support per release, verified vs. unverified upgrade paths.
- **Release checklist** (`docs/release_checklist.md`): the two-PR release process used since
  v0.5.0, generalized and made reusable.
- **Historical fixtures and contract tests**: `tests/fixtures/v0.7.0/` (genuine release-asset
  manifest/checksums) and `tests/test_contract_freeze.py` (15 tests locking in every frozen
  interface against live code); `tests/test_documentation_consistency.py` grew from 22 to 37 tests.

## 3. Why it matters

- This project's public promises -- which command names and parameters, which report/batch
  contract shapes, which status and error literals -- are now explicit and enumerated in one place,
  rather than implicit in scattered prose.
- Those interfaces are now regression-locked: an accidental change to a frozen command signature,
  status literal, or contract identifier fails a test, not just a manual review.
- A new user can install, start, run, inspect, troubleshoot, and upgrade without ever needing to
  understand this project's internal development-stage numbering.
- Future changes toward v1.0 now have a defined compatibility boundary and a documented process for
  crossing it deliberately, rather than by accident.

## 4. User impact

- **No migration needed.** No user-data migration, cache migration, or report-schema migration is
  required or performed -- the cache format, report schemas, and batch contracts are byte-for-byte
  unchanged from v0.7.0.
- Existing outputs, reports, and batch plans remain exactly where you left them; nothing is moved,
  converted, or rewritten by this upgrade.
- Batch review history remains session-only, unchanged.
- Install through PyMOL Plugin Manager using clean replacement, then fully restart PyMOL -- see
  [docs/quick_start.md](quick_start.md) and [docs/upgrade_guide.md](upgrade_guide.md).

## 5. Installation

After publication, download `MembraneVisualQC-0.8.0.zip` and `MembraneVisualQC-0.8.0.zip.sha256`
from the v0.8.0 GitHub prerelease. Verify the checksum, install through PyMOL Plugin Manager using
clean replacement (recommended over overlay -- see
[docs/upgrade_guide.md#3-recommended-installation-method](upgrade_guide.md#3-recommended-installation-method)),
and fully restart PyMOL. See [docs/quick_start.md](quick_start.md) for the complete first-run
walkthrough.

## 6. Compatibility

- Report schemas 1.0-1.5 (`single_structure_review` family 1.0-1.4, `orientation_source_comparison`
  1.5) are unchanged and immutable, per `docs/report_schema.md`.
- Batch contracts `mvqc-batch-plan-1.0` / `mvqc-batch-result-1.0` are unchanged exact-string
  identifiers, per `docs/v1.0_contract_freeze.md#2-batch-contracts-frozen`.
- Cache format `cache-v1` is unchanged; no migration exists because none is needed.
- The batch output/manifest directory layout is now declared the frozen v1.0 candidate contract --
  see `docs/outputs_and_manifests.md#what-is-stable-vs-not-yet-frozen`.
- No PyPI publication is provided or planned; GitHub Releases remains the sole distribution
  channel.
- Validated target environment: see `docs/compatibility.md` and `docs/compatibility_matrix.md` for
  the current OS/PyMOL-distribution/Python-version grid -- unchanged from v0.7.0.

## 10. What remains before v1.0

Not attempted or claimed by this release:

- the premium README redesign and project visual identity (deferred to a dedicated v0.9.0 session);
- professional GUI/UX polish or a visual redesign;
- release-candidate hardening or external validation beyond this project's own manual matrix;
- a final, non-prerelease stable release -- v0.8.0 remains a GitHub prerelease, as have v0.5.0
  through v0.7.0, since a documented contract is not yet the same as one proven stable across a
  post-freeze release cycle.
